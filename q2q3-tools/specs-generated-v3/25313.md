## Interface the tests expect

The change is checked by unit tests that use the following code locations and signatures. Create or extend them exactly as named. Everything else about the implementation is up to you.

**New file `packages/lib/pkce.ts`**, exporting:
```ts
export function verifyCodeChallenge(codeVerifier: string, codeChallenge: string, method?: string): boolean
export function isValidCodeChallengeMethod(method: string): boolean
```

**Prisma schema (`packages/prisma/schema.prisma`)**, additions:
```prisma
enum OAuthClientType {
  CONFIDENTIAL
  PUBLIC
}
model OAuthClient {   // existing; changes only
  clientType OAuthClientType   // new
  clientSecret String?   // was String
}
model AccessCode {   // existing; changes only
  codeChallenge String?   // new
  codeChallengeMethod String?   // new
}
```

**Dependencies the tests replace with mocks.** The code under test should get its data through these modules and members, because the tests stub them instead of using a database. A mock defines only the members listed, so importing anything else from these modules fails under the tests:

- `@calcom/prisma`: `default`
- `app/api/defaultResponderForAppDir`: `defaultResponderForAppDir`
- `app/api/parseRequestData`: `parseUrlFormData`
- `jsonwebtoken`: `default`, `default.sign`
- `next/server`: `NextRequest`, `NextResponse`
- `packages/lib/pkce.ts`: `verifyCodeChallenge`
- `packages/trpc/server/routers/viewer/oAuth/addClient.handler.ts`: `generateSecret`

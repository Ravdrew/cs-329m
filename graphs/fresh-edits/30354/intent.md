Show real calendar event titles instead of "Busy" to the calendar owner. In CalendarManager, getCalendarsEvents gets an "overlay" mode: only in that mode, and only for the logged-in user's own credentials, it asks the calendar service for busy times with titles when the service supports it, falling back to plain getAvailability if fetching titles fails; other modes stay untitled so titles never reach anyone but the owner. Implement getAvailabilityWithTitles in the Google Calendar service and the Office365 calendar service (no change to Google OAuth scopes), and have CalendarTelemetryWrapper pass it through. The availability.user tRPC handler requests overlay mode only when the requested user is the logged-in user, compared by user id since usernames repeat across organizations.

The troubleshooter (availability UI) shows event titles for calendar busy times and multi-day events on every day they cover. The weekly view (calendar views) draws an event on every day it covers, clipped to that day, so events spanning midnight and all-day or multi-day events no longer appear only on their first day; overlay busy times show their titles.

In the booker, the overlay calendar starts with the calendars selected for conflict checking and loads them right away for the visible date range, instead of the primary calendar only after a manual toggle. The hover card of a conflicting slot on the confirm button shows the overlapping event's title and time range, with dates on both ends for events crossing midnight. The overlay continue modal offers the instance's enabled social logins, fetched from next-auth once the modal opens; signing in with Google or Microsoft also connects that calendar and brings the user back to the booking page with the overlay on.

Persist wrong assignment reports. Add a new WrongAssignmentReport model (in the Prisma schema, accessed through a new WrongAssignmentReportRepository) that stores at most one report per booking, enforced by a unique index on booking uid in the migration. Each report has a review status (PENDING, REVIEWED, RESOLVED, DISMISSED) and new reports start as PENDING. It links to the booking, the reporting user, the team and the routing form the booking came through; deleting the reporter or the team keeps the report and just clears that link. Bookings gain the link to their reports, and the BookingRepository lookup used by the report handler should also return the id of the routing form the booking was routed from.

In the tRPC viewer.bookings router, reportWrongAssignment should check for an existing report, then save the new one (with the reporter, team and routing form id) and return the new report's id. A duplicate report for the same booking is rejected with BAD_REQUEST and the translated `wrong_assignment_already_reported` message, including when two submissions race. Add a hasWrongAssignmentReport query that says whether a booking already has a report and throws UNAUTHORIZED if the user cannot access that booking.

In the bookings UI, the Report wrong assignment dialog calls hasWrongAssignmentReport when it opens; if a report already exists it shows a warning and disables Submit. Also fix the team member select so that clearing the selection resets the form value to empty.

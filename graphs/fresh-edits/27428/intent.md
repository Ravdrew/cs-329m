Add keyboard shortcuts to the booking details slideover (BookingDetailsSheet in the booking list and calendar views): Up Arrow goes to the previous booking, Down Arrow to the next, Escape closes the sheet, and Enter opens the join-meeting link when one is shown. The previous, next, close and join buttons each show a tooltip naming their shortcut, using new translated labels in common.json; JoinMeetingButton should accept a ref from the sheet and optionally render its own tooltip. Put the key handling in a new standalone utility, `apps/web/modules/bookings/lib/bookingSheetKeyboardHandler.ts`, which the sheet registers on keydown in the capture phase so shortcuts run before a focused button reacts, passing it the sheet's navigation state, previous/next actions and join link.

Rules for the handler: ignore keys while typing in an editable field. The sheet counts as active when nothing has focus, when focus is inside the sheet, or when focus is not inside any Radix portal; if focus is in some other overlay (dialog, dropdown, popover), shortcuts are suppressed. While active, Up/Down are always consumed (default prevented and propagation stopped), even at the first or last booking, so the booking actions dropdown never opens from an arrow key; navigation only happens when a previous/next booking exists and no transition is in progress. Enter opens the join link and is consumed only when a join link exists. All other keys pass through.

Also fix the calendar view: booking events in the weekly calendar (Event.tsx) should carry the booking uid and a marker identifying them as booking calendar events, and the sheet's outside-interaction check should treat clicks on either booking list items or booking calendar events as navigation, keeping the sheet open rather than closing and reopening it.

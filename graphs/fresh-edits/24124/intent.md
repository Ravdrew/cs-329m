Make calendar sync push external changes back into Cal.com. In the calendar subscription and sync component, CalendarSyncService should process only events whose UID maps to a Cal.com booking: when the event was deleted in Google Calendar or Office365, cancel the booking; when it was moved (only if the start time actually changed), reschedule it. Errors are caught and logged, never thrown, so the sync continues; a booking missing its user, user email or event type is skipped with a warning. Report Sentry metrics for each sync, cancel and reschedule (call counts by status success/error/skipped, number of events per sync, durations). Load the booking service lazily so the calendar webhook endpoint does not pull in the query-builder UI library at module load.

Cancelling goes through handleCancelBooking for that single booking (not the recurring series), acting as the booking's owner, with a new skipCalendarSyncTaskCancellation flag (added to bookingCancelSchema in zod-utils). When the flag is set, handleCancelBooking cancels the booking without asking EventManager to delete the external calendar event, which prevents a loop; booking references are still always marked deleted, whether or not the flag is set, since the external event is already gone.

Rescheduling goes through RegularBookingService.createBooking with the booking's rescheduleUid and the new event times, reusing the booking's existing responses, with an idempotency key and the existing skipCalendarSyncTaskCreation flag on so the change is not written back to the external calendar.

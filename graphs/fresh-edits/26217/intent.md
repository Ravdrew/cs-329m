In the Signup endpoint, both `calcomHandler` and `selfHostedHandler` should check, when a signup carries a team/org invite token, whether a user with the invited email already exists before creating the account. If one does, they stop and return a 409 "user already exists" error instead of continuing the signup flow. Signups with an invite token for a new email, and signups without a token, behave as before.

Move the signup request out of the signup form into a new client-side signup fetch module (`packages/features/auth/signup/lib/fetchSignup.ts`, with shared signup error codes in `packages/features/auth/signup/constants.ts`) that posts the signup data, including any invite token and Turnstile token, to the signup API and returns a typed result. It must never throw on a bad response: an unreadable server response is reported as an invalid-server-response error, and a 409 is recognised as user-already-exists, so callers can tell that case and a checkout-session response apart from other failures.

When the signup form gets user-already-exists for an invite token, it shows a translated toast telling the user they already have an account and redirects them to the login page.

Replace the plain rotating loader shown while an embedded booking page loads with a skeleton UI that mimics the page being loaded, for both inline and modal embeds in the Embeds component (embed-core). Embed setup should detect the page type (user or team event, slots view or booking form) and the layout and pass them along so the right skeleton is chosen; when no page type is known, show the default loader as before. The inline HTML template in `Inline/inlineHtml.ts` becomes a function of layout and page type.

Add a shared base custom element, `EmbedElement` (`packages/embeds/embed-core/src/EmbedElement.ts`), that the inline and modal embed elements build on, each supplying whether it is a modal and how to get skeleton content for a layout and page type. It shows the skeleton when a page type is known and otherwise the default loader, and hides both once the iframe reports the page is ready. The skeleton follows the embed's theme (light/dark), falling back to the system colour scheme and updating live when that changes; it adapts to the layout (mobile on small screens) and resizes with the window. The skeleton container keeps a height so the embed does not jump when real content arrives, capped to the modal height in a modal.

Add embed UI helpers in `packages/embeds/embed-core/src/ui-utils.ts`, used by `EmbedElement`: resolve the effective layout (mobile below a small width), whether a theme was explicitly chosen and the theme class to apply, the max height for a modal, and one shared dark colour scheme query that `EmbedElement` subscribes to while connected and unsubscribes from when removed.

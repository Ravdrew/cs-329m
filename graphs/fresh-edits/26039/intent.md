Add configurable "Write to HubSpot Meeting" support (CAL-5031) to the HubSpot CRM service, part of the CRM integrations component. When the HubSpot app's event-type settings turn on writing on booking, each configured property mapping is resolved from the booking and set on the HubSpot Meeting when it is created. Before writing, the configured properties are checked against the HubSpot Meeting object's properties and any that do not exist are skipped. The HubSpot app data schema gains the on/off switch and the mappings, and the service reads app options through its existing getAppOptions.

Add a shared CRM write-to-object module (`packages/app-store/_lib/crm-enums.ts` and `crm-schemas.ts`) describing a mapping's field type, value and when to write it, used by both the HubSpot service and a new app card settings UI (WriteToObjectSettings, split into the component plus separate types and utils pieces). The UI offers a toggle for "On booking" writes and a list of mappings from a HubSpot property to a field type (text, date, phone, checkbox, custom) and value, including booking date choices.

Mapping values are resolved by field type: static text is written as-is; `{fieldId}` placeholders take the booking form response; `{utm:source}`, `{utm:medium}` and similar take the booking's UTM tracking data; text mixing placeholders and static text (e.g. `Hello {name}!`) is filled in; date types use the booking start date or the booking's created date; checkboxes take booleans. UTM data comes from a new Tracking repository (interface plus Prisma implementation in `packages/lib/server/repository/`) that looks up a booking's tracking record by booking uid and returns nothing if none exists; the booking's created date is fetched through the existing booking repository by booking uid.

Fix three bugs in how the weekly calendar view (the Calendar views component under `packages/features/calendars/weeklyview`) displays overlapping events. First, each Calendar instance must get its own isolated weekly-view state instead of sharing one global Zustand store, so changing dates or events in one calendar on a page no longer affects other calendars on the same page. Second, overlapping events must stay inside their own day column even with 10 or more (up to 20+) overlapping events. Third, event positioning must no longer use the `inset-x-1` class, which sets both left and right and conflicts with the inline width.

Move the overlap layout into a new set of pure helpers in `packages/features/calendars/weeklyview/utils/overlap.ts`. They sort a day's events, group the ones that overlap in time, and compute a cascading left offset, width and stacking order for each event so that offset plus width stays within the day column (allowing a safety margin) however many events overlap. The base width, offset step, z-index and margin have defaults that callers can override. The weekly view's event list then takes each event's left offset, width and z-index from these helpers instead of computing the cascade itself.
